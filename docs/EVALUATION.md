规则层直接解析 agent 最终 `answer` 中的 `[product_xxx]` 引用，与检索返回集交叉校验：

| 用例 | 查询 | faithful | hallucination | context_util | 结果 |
|---|---|---|---|---|---|
| G01 | 预算3000以内推荐一款拍照好的手机 | ✓ | 0.0 | >0 | ✓ |
| G02 | 2000元以内的降噪耳机哪个好 | ✓ | 0.0 | >0 | ✓ |
| G03 | 8000元以上的轻薄笔记本推荐一下 | ✓ | 0.0 | >0 | ✓ |

| 断言类 | 用例 | 结果 |

## 四、本次会话修复的两个后台 Bug

### 4.1 长期记忆元数据写入失败（ChromaDB 1.5.9 Rust 绑定）

- **现象**：轮末后台任务把对话写入长期记忆时报错，`user_id` 为 `None` 时 ChromaDB 1.5.9 的 Rust 绑定**拒绝 None 元数据值**。
- **根因**：`loop.py` 向 `long_term_memory.add()` 传的是原始 `user_id`（可能为 None），而非归一化后的 `owner_uid`。
- **修复**：`src/harness/core/loop.py` → `user_id=owner_uid`。验证：`_dbg_ascii.py` 重跑 EXIT=0，日志无元数据验证错误、`bg tasks left: 0`。

### 4.2 小模型请求头 ASCII 编码错误（pydantic-settings 注释污染）

- **现象**：小模型旁路调用（事实抽取/重排）时抛 `UnicodeEncodeError`。
- **根因**：`.env` 中 `OPENAI_SMALL_API_URL/KEY/MODEL` 空值后跟**行内中文注释**，pydantic-settings 把注释文本解析成 api_key 值，中文进入 HTTP 请求头 → httpx 对 header 值做 ASCII 编码失败。
- **修复**：`.env` 与 `.env.example` 将行内注释移到独立注释行，确保空值正确解析。验证：重跑无 ascii 错误。

## 五、发现的问题（在线层失分根因）

1. **主模型工具调用不稳定（最高优先级）**：当前主模型 `astron-code-latest`（讯飞代码模型）对「订单/物流/政策」类意图路由弱，误落入 `transfer_human` / `knowledge_retrieval` 兜底；多轮后续轮次（含指代「那款/那个」）常直接对话不调用工具。**建议**：评测路由/任务流程时切换通用对话模型（如 DeepSeek / Qwen 系列）复测，或对兜底工具 `transfer_human` 加强路由提示词。
2. **引用协议不遵守**：G05 回答无 `[product_xxx]` 引用 → ContextUtil=0。生成 prompt 需强化「必须带商品引用」指令，并给负例。
3. **R19/R17 检索弱项**：头戴耳机 recall@5=0.50、HiFi 耳机 MRR=0.25——意图词表需补充「头戴」「HiFi」等细分词。
4. **端到端延迟 p95=6.3s**：主模型生成慢，客服场景建议接入流式输出 + 小模型重排降首token。
