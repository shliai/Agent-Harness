# Agent Harness 功能说明文档

> 版本：v0.7.4 · 架构详情见 [ARCHITECTURE.md](ARCHITECTURE.md) · 接口规范见 [API.md](API.md)

## 系统定位

基于 ReAct 模式的电商客服 Agent 运行时。LLM 负责推理与参数抽取，Harness 负责循环调度、工具执行、数据访问、记忆管理、安全控制与可观测性。

**核心边界**：LLM 不直接访问数据库——它输出结构化的工具调用意图，工具层校验后执行 I/O。

---

## 一、对话能力

### 1.1 ReAct 循环

每轮对话按 Thought → Action → Observation 循环执行，直到 LLM 认为信息足够输出最终回答，或达到最大迭代次数（默认 6 步）。

- **流式输出**：回答以 token 级增量实时推送到前端
- **失败重试**：工具执行失败时自动让 LLM 修正参数重试
- **格式自愈**：LLM 输出的 ACTION JSON 格式错误时纠正重试，不把残片当答案
- **中断保护**：用户停止或断网时已生成的部分内容落盘保存
- **空回复兜底**：LLM 返回空内容时生成友好提示而非空气泡

### 1.2 上下文工程

每轮请求的上下文按以下顺序装配：

```
[system 人设+工具] → [system 冻结章节×k] → [历史消息(只追加)] → [system 状态尾注=当期WM+跨会话召回] → [本轮输入]
```

| 组件 | 说明 |
|---|---|
| 系统提示 | 角色设定 + 行为规范 + 预算约束 + 政策要求 + 引用规范 |
| 工具说明 | 从 Registry 动态生成的工具描述 |
| 冻结章节 | 超窗对话压缩为不可变章节（含当期 WM 快照），旧章节永不改写、缓存不失效 |
| 工作记忆 | 结构化槽位（预算/订单号/物流号/话题）+ LLM 实体事实，确定性规则抽取 |
| 长期记忆 | ChromaDB+BGE 语义召回的相关历史片段 |
| 消息窗口 | 最近 SHORT_TERM_WINDOW 条原始消息（只追加） |

> **小模型旁路**：事实抽取、检索重排等旁路低风险调用可配置 `OPENAI_SMALL_MODEL` 走低成本
> 小模型（URL/KEY 留空继承主网关，MODEL 留空自动回落主模型），不占用主模型配额与限流。

### 1.3 多轮一致性

- **预算记忆**：「预算3000」→ 后续推荐持续遵守；「改成5000」→ 自动更新
- **实体追踪**：会话中提到的订单号、物流单号全程可引用
- **澄清式追问**：缺少必要信息时先查已有数据补全，无法补全时一次性提出明确问题

## 二、工具系统

### 2.1 商品检索 `knowledge_retrieval`

| 能力 | 说明 |
|---|---|
| 混合检索 | BGE 向量语义 + BM25 关键字，RRF 排名融合 |
| 中文分词 | jieba（可选）或内置 ASCII+CJK 二元组分词器 |
| 价格过滤 | 元 / 块 / k / 千 / 万 单位识别；「万元以上」等中文表达归一化 |
| 品类过滤 | 手机 / 笔记本 / 平板 / 耳机 / 穿戴 / 配件等 |
| 预算加权 | 匹配意图词的商品优先排序；越接近预算上限排名越高 |
| 库存展示 | 输出中标注库存充足/紧张/售罄状态 |
| 自校正 | 向量距离超阈值时自动放宽价格条件二次召回 |
| 在售过滤 | 下架商品即使向量残留也不会被召回 |

### 2.2 订单查询 `order_query` / `order_list`

| 能力 | 说明 |
|---|---|
| 归属校验 | 只能查询本人订单，他人订单返回拒绝提示 |
| 列表查询 | 不记得订单号时列出全部本人订单 |
| 枚举风控 | 同会话连续 8 次未命中即熔断 30 分钟 |

### 2.3 物流查询 `logistics_query`

物流轨迹查询，支持 SF/YT/ZTO/JD/EMS 承运商前缀校验与枚举风控。

### 2.4 售后服务 `after_sale_apply` / `after_sale_query`

| 能力 | 说明 |
|---|---|
| 申请创建 | 退货/换货申请，支持指定件数（部分退） |
| 退款测算 | 平台券按件均摊不退；满减整单退时全额扣回；部分退不扣回 |
| 状态机 | 待审核 → 已通过 → 已完成 / 已拒绝（唯一流转出口） |
| 幂等防重复 | 同订单进行中的售后单不会重复创建 |
| 进度查询 | 用户名下所有售后单及当前状态 |

### 2.5 政策查询 `policy_query`

结构化政策库检索（10 条官方条款）。政策类问题强制查库后引用条款编号回答，未命中引导转人工而非编造。

覆盖范围：七天无理由退货 / 质量问题退换 / 退款时效 / 整机保修 / 价保规则 / 发票开具 / 配送时效 / 换货流程 / 物流赔付 / 账户安全。

### 2.6 转人工 `transfer_human`

触发条件：用户明确要求人工 / 同一问题尝试 2 次仍无法解决 / 投诉赔偿等超权限事项。
行为：创建工单（工单号+原因+关联订单），返回确认话术。

### 2.7 计算 `calculator`

AST 白名单求值，支持四则运算、幂运算（限制指数规模）、括号嵌套。无 eval 注入风险。

### 2.8 子任务分发 `subtask_dispatch`

复杂任务拆分为多个隔离子任务依次执行。子任务内禁止递归调用自身，输出过护栏脱敏。

## 三、记忆体系

| 层 | 模块 | 数据源 | 特点 |
|---|---|---|---|
| 工作记忆 | working_memory.py | 规则抽取用户输入 | 结构化槽位：预算(金额/品类/轮次)、订单号、物流号、近期话题、澄清等待项。确定性零开销 |
| 短期记忆 | short_term.py | 对话消息 | 只追加列表（不滑动淘汰，避免打穿 KV cache 前缀）；达触发阈值时显式压缩 |
| 会话压缩 | loop 内置 | 消息估算 token ≥ 窗口×比例 | LLM 章节式滚动摘要（≤ CONTEXT_SUMMARY_MAX_CHARS 字），冻结章节追加+WM快照；保留预算/单号/结论/未决诉求 |
| 长期记忆 | long_term.py | ChromaDB + BGE | 跨会话语义召回，user_id 隔离，距离阈值过滤，后台异步写入 |

## 四、安全护栏

流水线顺序执行，任一拦截即短路并写入审计日志（passed/blocked 全留痕）：

| 护栏 | 拦截范围 | 行为 |
|---|---|---|
| InputValidator | 空值 / 超长 / 控制字符 | 拒绝请求 |
| InjectionGuard | 中英文 Prompt 注入特征 | 拒绝请求（可关） |
| OutputFilter | PII 掩码（身份证含X/手机号/银行卡/API Key） | 替换为 *** 并追加提示 |
| ComplianceFilter | 绝对化承诺（百分百能退等） | 追加合规提示并告警 |
| RateLimiter | 按会话限频（60次/分钟） | 返回等待时间 |
| AuditLogger | 全事件审计留痕 | JSONL 文件，按 AUDIT_ROTATE_MB 轮转 |

**额外保护**：
- 订单归属校验（他人订单不可查）
- 枚举风控（连续未命中熔断）
- 会话 ID 白名单（防路径穿越）
- 参数格式白名单（畸形参数计入风控计数）
- 输出脱敏前移（先过滤再入记忆/历史）

## 五、评测体系

五层评测框架（`scripts/eval.py`），用例定义于 `data/eval/golden_set.jsonl`：

| 层 | 指标 | 方式 |
|---|---|---|
| retrieval | Recall@5 / MRR / 价格品类硬合规 | GT 从 SQLite 运行时计算 |
| budget | 超预算数（零容忍）/ top1 接近度 | 离线 |
| routing | 工具路由命中率 | --live（消耗真实 tokens） |
| robustness | 幂炸弹秒拒 / 代码注入 / PII 脱敏 / 限流隔离 / 路径穿越 | 离线 |
| memory | 长期记忆语义召回命中 | 离线 |

辅助脚本：`scripts/export_badcase.py` 从审计日志和失败轨迹导出 badcase 候选。

## 六、部署

```bash
# 本地开发
pip install -e ".[dev]"
python scripts/init_db.py --reindex
python -m harness.main

# Docker 生产
docker compose up -d
```

CI（GitHub Actions）：ruff 关键规则门禁 → pytest → main 分支镜像构建验证。
